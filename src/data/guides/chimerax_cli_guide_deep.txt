UCSF ChimeraX Command-Line Guide (Comprehensive)

This guide covers UCSF ChimeraX command-line interface usage, organized by functionality. It includes descriptions, syntax examples, and notes for visualization, selection, transformation, coloring, measurement, modeling, analysis, file I/O, animation, and more. It is designed as a reference for translating natural language instructions into ChimeraX CLI commands.

    General Conventions: ChimeraX commands are case-insensitive and can be abbreviated to the shortest unique prefix. If a command expects a target specification (atoms, residues, models, etc.) and none is given, it defaults to all applicable items. Many commands have a “~” negation form (for example, ~show is equivalent to the hide command). Use semicolons (;) to separate multiple commands on one line. If a file path or name contains spaces or special characters (like # or :), enclose it in quotes.

File I/O and Session Management

Opening and Fetching Data – open: Loads structures, maps, sequences, or other data from a file, URL, or database. You can open local files by path or fetch data by identifier. For example, open 7k00 will fetch PDB ID 7K00 from the RCSB database, and open emd:1122 fetches EMDB map 1122. Use open URL to open web content or fetch by URL. ChimeraX recognizes many formats automatically; use open formats to list supported formats in the log. The command can also open multiple files (e.g., using wildcards or foreach) and trajectories (see Animation below). Syntax: open <filename|URL|databaseID> (with options like format, maxModels, etc. as needed). Example: open "myfolder/model.pdb" (local file), open 1tqn (fetch PDB 1TQN from RCSB). Note: If the file type isn’t recognized by suffix, specify format; e.g., open data.txt format pdb. A blank open without arguments re-opens the file browser GUI if available. Use quotes for paths with spaces.

Saving Sessions, Structures, and Images – save: Saves the current session, displayed image, molecular data, or other content to a file. Syntax: save <filename> [format <type>] [models <model-spec>]. The format is inferred from file extension or can be given explicitly (use save formats to list possible output formats). For example, save session.cxs saves the entire session (ChimeraX session format, not compatible with Chimera). To save a molecular model to PDB format, include the .pdb extension (or format pdb) and optionally restrict to a specific model: e.g., save mutated.pdb #3 saves model #3 as a PDB file. To save a publication-quality image, use an image extension like .png: e.g., save figure.png supersample 3 (the supersample option improves image quality by oversampling). Note: Sessions (.cxs) preserve all open models, display settings, etc., but are version-specific. Common Mistake: Forgetting to include a file extension – if omitted, ChimeraX might not know what format to use. Always add the proper extension or use the format option. Also, saving atomic coordinates to PDB may lose certain data (like per-atom attributes that aren’t supported in PDB format).

Closing Models or Sessions – close: Removes models or data. Syntax: close <model-spec> or close session. For example, close #2,3 closes models 2 and 3. close session closes all models and resets many global settings (like camera, clipping, background) to defaults. Note: A bare close (no spec) also closes everything (same as close session). Use carefully to avoid unintentionally clearing all data.

Working Directory – cd and pwd: cd <directory> changes the working directory (affecting relative file paths). pwd prints the current working directory path. Example: cd ~/projects/ then open relative_path/model.pdb.

Exiting – exit/quit: Closes ChimeraX. Any unsaved session data will be lost. Syntax: exit (or quit). This can be used in scripts to terminate the program after automated tasks.

Logging – log: Manages the Command Log output. You can log save <filename> to save the contents of the log to a text file, log clear to clear it, etc. This is useful in recording outputs of measurement commands. (The log panel can also be shown/hidden via GUI or log show/hide.)

Help and Usage Info – help and usage: help <command> opens the help documentation for that command in the ChimeraX browser. For quick syntax reminders, usage <command> prints a brief summary in the Log. Example: help color opens the full manual page for the color command, while usage color prints its usage syntax summary in the log. This is useful for checking available options.

Selection and Model Specification

Selecting atoms, residues, or models is often the first step to limit the scope of other commands:

Selecting Items – select: Highlights specified atoms, residues, or models for subsequent operations. Basic Syntax: select <spec> where <spec> is an atom/residue/model specification. A blank specification means select all. For example, select protein selects all protein atoms in all models (built-in classification), and select #1:10-50.A selects residues 10–50 in chain A of model 1. The selection is shown as green outlines in the viewport. Common selectors include protein, nucleic, solvent, ligand, element symbols (e.g., @Fe for iron atoms), etc.. You can also specify by sequence or use wildcards (e.g., :/ALA for all alanines). Modifiers: select add <spec> / select subtract <spec> / select intersect <spec> will modify the current selection; select clear (or ~select) clears the selection. Use the up/down arrow keys or select up/select down to expand or contract the selection hierarchy (e.g., from an atom to its whole residue). Zone Selection: select zone <ref-spec> cutoff <distance> selects all atoms within the given distance of the reference specification. For example, select zone ligand 4.5 protein selects protein residues within 4.5 Å of any ligand atom. Note: Selecting something doesn’t automatically restrict commands to it – you must either specify sel in the command or rely on commands that inherently act on the selection. E.g., after selecting, use color sel red to color the selection. Common Mistake: Assuming a command will apply only to the selection without specifying it. Always provide sel (or the named selection) in the command if you intend to target the current selection.

Naming Selections – name: Assigns a nickname to a set of atoms/residues for easy reuse. Syntax: name <aliasName> <spec>. After this, you can use <aliasName> in place of the specification in other commands. For example: select /A:1-100, then name region1 sel defines the current selection as “region1”. Later, color region1 blue would color that same set of atoms blue. Named targets persist in the session and can be listed with name list or removed with name delete. Note: Use name frozen <alias> <spec> if you want the alias to remember the exact current atoms (even if models are closed or the selection changes). The regular name (without “frozen”) will re-evaluate the specification each time it’s used.

Specifying Atoms/Residues: Many commands take an atom specification string to identify targets. The general format is #<model>:<residue><chain>@<atom>. Omitted parts are wildcards (e.g. #0:50@CA means all Cα atoms in residue 50 of model 0; #0:50 means residue 50 in all chains of model 0). Ranges and lists are allowed (e.g., #2:A:1-100 or #2:A:1,5,10 for specific residues). Use # for model, / for chain, : for residue, @ for atom. The special keyword sel refers to the current selection, and ~ before a spec means logical NOT (negation). For example, color ~sel gray would color everything except the current selection gray. Built-in keywords: ChimeraX has shortcuts like ligand (non-polymer hetero residues), solvent (water), protein, nucleic, secondary structure classes (helix, sheet/strand), etc.. You can combine specifiers with logical operators like & (and), | (or). Example: select protein & helix selects all helical residues in proteins.

Inverting & Combining Selections: As noted, ~select inverts a selection if used with ~sel specifier (e.g., select ~sel selects everything not currently selected). You can also invert within a model: select ~sel & #1 (selects all in model 1 that were not selected, while leaving other models unchanged). Use &, | to combine criteria, e.g., select protein & ~helix to get all non-helical protein residues.

Visualization: Display Styles and Geometry

Displaying or Hiding Atoms – show / hide: Controls the visibility of atomic model components. Syntax: show <spec> [target level] and similarly hide <spec> [target level]. If no target level is given, the default is to show/hide atoms (and bonds). For example, show #1:1-100 will display residues 1–100 of model 1 (atoms/bonds that were previously hidden), and hide solvent hides all water molecules. You can specify different levels: target a for atoms, target b for bonds, target c (or ribbons) for cartoon ribbons, target s for molecular surfaces, target m for whole models. Alternatively use keywords: atoms, bonds, cartoons, surfaces, models as the level. Examples: hide #1/A:50-100 cartoons hides the ribbon (cartoon) for residues 50–100 of chain A, model 1, without hiding the atoms. show nucleic target r shows ribbon (helix/ladder) representation for nucleic acid residues (DNA/RNA) if they were hidden. Note: Hiding all atoms of a residue will also hide its bonds automatically. Use ~show as shorthand for hide (and ~hide for show) if needed. Common Mistake: Not specifying the correct target – e.g., hide #1 by default hides atoms but not ribbons/surfaces. If a protein is shown as a ribbon, use hide #1 target r to hide the ribbon or it may appear nothing happened.

Atomic Display Style – style: Sets how atoms and bonds are drawn (sphere, stick, ball-and-stick, etc.). Syntax: style <spec> [sphere|stick|ball] [ringFill option] [dashes N]. The primary modes are: sphere (space-filling, van der Waals radii); stick (sticks with a default radius); ball (ball-and-stick, small atoms with sticks). Example: style protein stick shows all protein atoms as sticks. style ligand sphere for a space-filling ligand. The ringFill option controls how aromatic rings are filled: e.g., ringFill thick or thin to fill rings with a disk (matching stick thickness); off to not fill rings. The dashes option sets how many dashes to use for pseudobonds (dashed lines, like distance monitors): dashes 0 makes pseudobonds solid. Note: You can adjust sizes with the size command (see below). The style command doesn’t affect ribbons (cartoons) – that’s controlled by cartoon styles (below).

Cartoon (Ribbon) Representation – cartoon: Displays biomolecular backbone as a ribbon or tube. (cartoon and ribbon are synonyms in ChimeraX.) Syntax: cartoon <spec> [option value …]. Simply using cartoon <spec> will show a ribbon for the specified residues. For example, cartoon #1 draws a ribbon for all chains in model 1, hiding the atomic detail by default (you can still show both if desired). By default helices are shown as coils/tubes, strands as arrows. Options include style (to change ribbon style, e.g., style edgetrim for edged ribbons, or mode tube for simple tube), radius to adjust thickness, etc.. Note: Cartoon display only works for proteins and nucleic acids (polymers with secondary structure or connectivity). Use ~cartoon or hide #:.A cartoons to hide ribbons and see atoms instead. Common Mistake: Forgetting to hide atomic detail if showing ribbons – by default ChimeraX may hide atoms when ribbons are shown, but if not, you might see overlapping atoms and ribbons. Use hide <spec> atoms if needed to avoid clutter.

Nucleotide Depictions – nucleotides: Provides special representations for nucleic acids (DNA/RNA), such as ladder (lines between bases), slab (filled base planes), etc.. Syntax: nucleotides <spec> [layout {ladder|slab|stick}] [arrows true|false] .... For example, nucleotides #1 layout ladder arrows true will show base pairing as ladder rungs with arrows indicating 5’→3’ direction. This helps visualize nucleic acid structures.

Surfaces – surface and ~surface: Generates molecular surfaces for specified atoms and displays them. Syntax: surface <spec> will create/show a solvent-excluded surface for the specified atoms (defaults to all atoms if none specified). Example: surface protein shows the surface for all protein molecules. Conversely, ~surface <spec> (or surface off <spec>) hides and removes the surface for that spec. Note: The first time you call surface on a model, it computes a surface as a separate surface model (usually with a .1 model number extension). The surface model can be closed with close or toggled later. Also, surfaces by default are shown for entire biological molecules; you can restrict surfaces to zones (see surface zone in Coloring section for map surfaces, or use select zone for atomic surface capping). Common Mistake: Trying to use surface on very large structures without enough memory – molecular surface calculation can be heavy. In such cases consider surface sphere approximation or hide dust to remove tiny disconnected surface pieces if applicable.

Clipping Planes – clip: Controls near/far and front/back clipping planes that cut away parts of the view. Syntax: clip near <dist> or clip far <dist> to set the global clipping plane distances (distance from camera). clip front <offset> and clip back <offset> define movable clipping planes that move with the scene (useful to slice through a model at a specific position). For example, clip front 10 will activate a front clipping plane 10 Å in front of the current center, cutting into the structures. clip off turns off all clipping. You can also do per-model clipping: clip model <model-spec> on/off to exempt a model from clipping (e.g., clip a surface but not the atomic model). Note: Clipping is especially useful for viewing internal pockets or cross-sections. You can adjust clipping interactively in the Graphics window via the Side View tool, or precisely via the command. The surface cap command can fill in cut surfaces with a cap if desired (see preferences).

Center of Rotation – cofr: Sets or reports the center of rotation for the camera. By default, ChimeraX auto-adjusts this based on the view (front center method). Syntax: cofr with no args reports the current center method; cofr fixed locks the current center as fixed; cofr frontCenter (or ~cofr) restores the default front-center auto mode. You can explicitly set the rotation center to a point or atoms: cofr <atom-spec> sets center to the centroid of those atoms, or cofr x,y,z for coordinates. Example: cofr #1:50 centers rotation on residue 50 of model 1 (useful to pivot around a certain residue). Note: A visible marker for the pivot can be toggled with cofr showPivot true to display a cross at the rotation center. This setting influences how the mouse rotation behaves (particularly in large scenes or if you zoom into a specific area).

Window and View Size – windowsize: Sets the graphics window pixel dimensions. Syntax: windowsize <width> <height>. For example, windowsize 1920 1080 for a full HD frame. This is important for generating images or movies at specific resolutions (often used before save or movie record).

Camera Projection – camera: Adjusts camera projection (perspective vs orthographic) and stereo modes. Syntax: camera orthographic true|false or camera mode stereo (with stereo parameters). In normal use, you might use camera ortho to get an orthographic projection (no perspective distortion) which can be useful for flat 2D images or comparison of distances.

Graphics Quality Settings – graphics and lighting: Use graphics to control overall rendering settings (like graphics silhouettes true to outline structures, or graphics transparencyQuality high). Use lighting to switch lighting presets that affect shadows and ambient occlusion. Example: lighting soft for ambient lighting with soft shadows (good for surfaces), or lighting default to revert to default lights (no shadows). These commands help improve image aesthetics. A quick preset: lighting full gives strong key light with shadows (like a full photoreal setup). Note: High-quality settings (like many shadows) can slow rendering; adjust based on needs.

Colors and Labels

Coloring Objects – color: Colors atoms, ribbons, surfaces, etc., a specified color. Syntax: color <spec> <colorname> [target level]. The <colorname> can be a named color (red, blue, gold, etc.), a hex code (#RRGGBB), or an element-based scheme like byelement. For example, color sel hot pink colors the selected atoms hot pink. color /A green target c colors only the cartoon (ribbon) of chain A green (leaving atoms unchanged). If no target is specified, ChimeraX decides based on context (atoms vs surfaces); you can explicitly specify targets with single-letter codes: a=atoms, b=bonds, c/r=cartoon ribbons, s=surfaces, p=pseudobonds, f=fill (ring fill and nucleotide base fills). For instance, color #1 cyan target s colors the molecular surface of model 1 cyan without affecting atoms. Rainbow Coloring: The rainbow keyword applies a spectrum of colors through a sequence of residues or chains. E.g., rainbow #1 will color residues in model 1 from blue to red across the sequence. Note: By default, color will override any previous coloring on those items. To remove coloring (revert to default), you might color by element or use ~color in certain contexts (e.g., ~color /A would remove per-atom coloring on chain A, but note ChimeraX doesn’t have a single “revert all colors” command except by re-opening or using preset). Common Mistake: Omitting the spec – remember color blue with no spec colors everything blue (blank means all). Use it carefully or specify a target.

Color by Attribute – color byattribute: ChimeraX can color by atomic attributes (like b-factor, conservation, etc.) using palettes. Usage: color byattribute <attribute> <spec> palette <paletteName> range <min>:<max>. For example, to color by B-factor: color byattribute bfactor #1 palette rainbow (this colors model 1 from blue to red by increasing B-factor). Similarly, color byattribute seq_rmsd #1 palette blue:white:red could color a model by RMSD values (if seq_rmsd attribute is present). This is an advanced usage and requires attribute data on the atoms. The rangecolor command is another way to map values to colors.

Coulombic Electrostatic Coloring – coulombic: Computes electrostatic potential on the fly and colors molecular surfaces accordingly. Syntax: coulombic <atom-spec> [options]. For example, coulombic protein will create a surface (if not present) and color it from red (negative potential) to blue (positive) by default. Options include distDep true/false (use distance-dependent dielectric, default true with ε=4r), dielectric <value> for constant ε, and offset <distance> to sample the potential slightly outward from the surface (default 1.4 Å). Note: The command automatically assigns charges (AMBER ff for standard residues or uses previously assigned charges). It will color the surface model, not the atoms themselves. Use key true option to show a color key legend for the potential range. Common Mistake: Using coulombic without any atoms loaded – it requires a structure with atoms (having reasonable partial charges) to compute the ESP. Also note that extremely large structures might make this slow.

Hydrophobicity Coloring – mlp: Calculates molecular lipophilicity potential and colors the surface from hydrophilic (cyan) to hydrophobic (goldenrod). Syntax: mlp <protein-spec> [options]. Example: mlp #1 will color model 1’s molecular surface by lipophilicity (ignoring non-protein atoms). By default, uses the Fauchère-Pliska hydrophobicity scale (can change via method option). Note: Like coulombic, this operates on the surface; ensure a surface is displayed for the protein or use the color true option to force color on surface (default color true). It will generate a surface if needed. Use key true to show a legend. This is useful for identifying hydrophobic patches on a protein.

Zone-based Surface Coloring – color zone: Colors surfaces near certain atoms to match those atoms’ colors. Typically used for coloring an EM map’s surface near a fitted model. Syntax: color zone <surf-spec> near <atom-spec> distance <d>. Example: if model #1 is a protein and #2 is a volume (surface) of a density map, color zone #2 near #1 distance 2.5 will color the map surface (#2) within 2.5 Å of any atom of #1 to the atom colors of #1. This effectively “paints” the surface by proximity to the model. Note: This requires the surface model and atomic model to be specified correctly. After coloring by zone, you can split the map by color segments with volume splitbyzone if desired.

Labels – label and ~label: Displays text labels tied to atoms, residues, bonds, or models. Syntax: label <atom-spec> [level] [text "<custom>"] [color <color>]. By default, labeling residues shows the residue name and number. For example, label :ASN@ND2 will label that atom with its name (ND2). label :50.A residues labels residue 50 in chain A (shows “<resname> 50”). Use label atoms to force atom names, or label bonds for bond lengths, etc.. To remove labels, use label delete <spec> or ~label <spec> (no spec = remove all labels). Options: color sets label color, height or size can adjust label font size, and text allows custom text instead of the default info. E.g., label :50.A text "Active Site" places a custom label on residue 50.A. Note: 3D labels move with the model. If you want annotations that don’t move (screen-fixed), consider 2D Labels. Also, labels will disappear if their associated atom/residue is hidden (e.g., hiding a labeled atom hides its label).

2D Labels – 2dlabels: Adds fixed text or symbols to the screen (for annotations in figures). These are not tied to atoms and won’t move when the model rotates. Syntax: 2dlabels create text "Label" color yellow coord 0.1,0.2 (using a normalized screen coordinate) etc. This is more advanced; see the 2dlabels documentation for details. Useful for arrows or captions on snapshots.

Color Key Legend – key: Draws a small color key bar with labels (used after coloring by attribute, ESP, etc.). Syntax: key <color1>:<label1> <color2>:<label2> ... [other options]. For example, after coulombic, you might do: key red: "-5 kT/e" white: "0" blue: "+5 kT/e" to indicate the potential range (the quotes allow spaces and symbols). The key will appear in the graphics window; you can adjust its position, size with options. This is not automatically generated (unless coulombic key true is used), so the key command is handy for custom legends.

Transparency – transparency: Adjusts the transparency (opacity) of atoms, surfaces, etc. Syntax: transparency <spec> <percent> [target ...]. Example: transparency #1 50 makes model 1’s surface 50% transparent by default (since surfaces are the default target). To make atoms transparent instead, specify target a (or use keyword atoms): e.g., transparency /Ligand 70 target a makes a ligand’s atoms 70% transparent (partially see-through). Multiple target types can be combined: transparency sel 30 target ac would make the selected atoms and cartoons 30% transparent. Note: 0% means fully opaque, 100% fully transparent. Transparency can help see internal parts of structures or overlapping components. However, due to graphics limitations, overlapping transparent objects might not render in strict back-to-front order (there are known limitations in rendering transparency). If transparency looks odd, try simpler scenes or see the graphics transparency quality settings.

Scale Bar – scalebar: Draws a scale bar in the viewport (useful for microscopy images or dimensional reference). Syntax: scalebar [length <value>] [units <unit>] [color <color>] .... For example, scalebar length 10 units Å color white to show a 10 Å scale bar. This is useful when presenting structures at a certain scale.

Measurements and Analysis

Distance Measurements – distance: Measures and displays distances between two atoms (or other points). Syntax: distance <atom-spec1> <atom-spec2> (simply specifying two atoms). This will draw a dashed line between the atoms and report the distance in the Log, continuously updating if the atoms move. For example, distance :50@CA :100@CA measures the Cα–Cα distance between residues 50 and 100. The result appears as a label on the dashed line and in the Log. The command can also create a series of distance monitors if multiple atoms are given (like a selection) but for pairwise distances, it’s usually two atoms. Note: The distance stays up-to-date – if you move the model (rotations don’t change distance, but translations or adjustments do), it will reflect new values. To remove a distance monitor, you can delete the pseudobond or use the command distance delete <atom-spec1> <atom-spec2> or simply ~distance (which removes all distance monitors). Common Mistake: Trying to measure distance between residues without specifying atoms – you must pick specific atoms (e.g., CA to CA, or a specific pair like NZ of Lys to OE1 of Glu for a salt bridge). There is no direct “residue-to-residue” distance, since distance is defined between points (atoms or markers).

Angles and Dihedrals – angle and torsion: The angle command measures the angle formed by three atoms (A–B–C, angle at B), and torsion (or dihedral) measures the dihedral angle of four atoms (A–B–C–D, the angle between planes ABC and BCD). Syntax: angle atom1 atom2 atom3 reports the ABC angle. For example, angle :50@N :50@CA :50@C gives the backbone angle at CA (which is the peptide bond angle phi or psi depending on context). torsion atom1 atom2 atom3 atom4 similarly reports the dihedral. These commands will output to the Log. They can also adjust angles if an angle value is given, but altering geometry this way has constraints (atoms must be connected appropriately). For instance, angle :10@CA :10@CB :10@CG 120 would attempt to set that bond angle to 120°. Note: Changing angles/dihedrals via command moves atoms and cannot be undone except by applying the opposite change or reloading the structure. For interactive angle adjustments, the graphical Adjust Torsions tool or mouse modes can be easier. Use ~angle or ~torsion to remove any visual markers.

Planar Measurements – define axes/planes/centroids: The define command can create geometric objects like an axis, plane, or centroid from sets of atoms. For example, define axis name Xaxis :10-50 will compute the principal axis through residues 10–50 and create a marker model for it. define plane :10,15,20 makes a plane through the specified three residues. Once defined, you could measure the angle between two defined axes with angle #axis1 #axis2, etc., or distance from a centroid to something. These are advanced but useful for structural analysis.

Hydrogen Bonds – hbonds: Identifies hydrogen bonds (and optionally halogen bonds) in a structure, based on geometry. Syntax: hbonds [<donor-spec> [<acceptor-spec>]] [distanceCutoff d] [angleCutoff a] .... With no arguments, it finds all H-bonds in the current selection or entire structure (if nothing selected) and shows them as dashed lines, listing them in the log. You can restrict donors/acceptors by spec, or use options to include water, etc. Example: hbonds protein protein would find protein intra- and inter-molecular H-bonds, ignoring water or other molecules. Note: The default criteria are distance ≤3.4 Å and angle ≥90° (for D–H...A angle) – which can be adjusted. H-bonds are shown as pseudobonds (usually cyan dashes). Remove them with ~hbonds if needed.

Contacts/Clashes – contacts (and clashes): Finds close contacts between atoms, either potential clashes (too close) or just contacts within a distance. Syntax: contacts <spec1> [<spec2>] [distance <d>] [log true]. Example: contacts /A /B distance 4.0 log true would list all atom pairs between chain A and B within 4 Å. The clashes command is similar but highlights steric clashes (typically using a smaller cutoff like <2.5 Å overlap). These commands can be useful for finding interfaces or problematic steric overlaps. Note: Results can be visualized as pseudobonds and also listed. The contacts command with log true will output pairs to the Log.

Surface Area and Volume – measure area/volume: Calculates area/volume of surfaces or enclosed cavities. For example, measure area #1.1 reports the area of surface model #1.1 (the surface for model #1). measure volume #1.1 reports the volume enclosed by that surface. For solvent-accessible surface area (SASA) of atoms, use measure sasa <atom-spec>. Example: measure sasa protein will report total SASA of all protein atoms (in Å^2), using a default probe of 1.4 Å (you can set probeRadius). There is also measure buriedArea :A withAtoms2 :B for interface buried area between chains A and B. Note: For measure area/volume to work, you need a surface generated (it works on surface models). measure sasa does not require a surface; it calculates analytically on the atomic radii.

Center of Mass – measure center: Computes the center of mass (or centroid) of specified atoms (and/or map density). Syntax: measure center <atom-spec> will print the coordinates of the center of those atoms. Optionally includes mass weighting or just geometric center.

Inertia Ellipsoid – measure inertia: Computes the inertial principal axes for a set of atoms and can show an ellipsoid. Syntax: measure inertia <atom-spec> – outputs moments of inertia and creates an ellipsoid model aligned with the inertial axes. Useful for shape analysis of assemblies.

Map Fitting and Correlation – fitmap and measure correlation: To fit an atomic model into a density map: fitmap #model inMap #map will move the model to the best fit position in the map (assuming they are roughly overlapped to start). After fitting, measure correlation #model #map can report the correlation coefficient of the map density vs model density at that position. These help in cryo-EM structure determination.

RMSD Calculation – rmsd: Computes the Root-Mean-Square Deviation between two sets of atoms without fitting. Syntax: rmsd <atom-spec1> <atom-spec2> (the two sets should be equal in number and order). This will report the RMSD in the log. If you want to fit then calculate RMSD, use align or matchmaker (below) which perform superposition.

Superposition – align and matchmaker: The align command directly superimposes two sets of atoms by least-squares fitting. Syntax: align <atom-spec1> <atom-spec2> – after which it will also report the RMSD. For example, align #1/A #2/A fits chain A of model 1 to chain A of model 2 (assuming same length/ordering) and gives RMSD. matchmaker (or its alias mmaker) is a higher-level tool to superimpose biomolecules using sequence alignment to pair residues. Syntax: matchmaker #1 #2 [criteria] – by default it will perform sequence alignment then fit. It’s very useful for comparing structures of related proteins (e.g., matchmaker #1 #2 might align chains automatically and superpose them). Note: align requires you to specify exactly which atoms correspond, whereas matchmaker tries to figure out corresponding residues (e.g., matching by sequence and secondary structure).

Sequence Alignments – sequence and match: The sequence command can fetch or display sequences and do alignment, but in CLI you might use match (not to be confused with matchmaker) to match sequences or search with BLAST (blastprotein). These are more specialized: e.g., blastprotein can search a sequence in PDB database and fetch hits.

Clustering Similar Structures – similarstructures: An advanced analysis command that can compare many related structures (e.g., from AlphaFold or NMR ensembles) to find clusters or representative sets. Not covered in detail here but note it exists for analyzing large sets of models.

Structure Editing and Modeling

Deleting Atoms/Bonds – delete: Removes specified atoms, bonds, or pseudobonds from a model. Syntax: delete <spec>. Example: delete solvent removes all water molecules. delete :100 deletes residue 100 (all atoms in it). You can also delete pseudobonds like distance monitors via delete pbonds or delete sel if you have selected bonds. Note: This actually modifies the structure (cannot be undone via undo, so be cautious). Deleting a backbone atom will also remove the attached sidechain and may affect connectivity of the chain.

Adding Hydrogens – addh: Adds missing hydrogen atoms to structures (e.g., to prepare for energy minimization or H-bond finding). Syntax: addh <spec> (if no spec, adds to all eligible models). This will place hydrogens in standard positions assuming appropriate chemistry (requires that the structure has correct standard atom names). Note: It will not add hydrogens to metal centers or other unusual cases perfectly; those might need manual adjustment.

Adding Charges – addcharge: Assigns partial charges to atoms (typically needed for electrostatics). Syntax: addcharge <spec>. By default uses Amber/GAFF for standard residues. It will also assign Amber atom types. The command will report what charge set was used. This is often used prior to coulombic coloring, or before writing a PQR file (via save) for APBS. Note: Requires standard residues; unknown residues won’t get charges unless parameterized via antechamber which ChimeraX tries to do automatically if possible.

Building and Modifying Structures – build: A versatile command for building structures or modifying bonds, angles, etc.. This includes subcommands for adding amino acids, adjusting bond lengths, etc. For example, build start gly creates a new glycine. The build modify subcommands allow changing bond lengths or angles similarly to the bond/angle commands but through one interface. For practical use, often the GUI tool Build Structure is easier; however, CLI can do things like build add Helix length 10 to add a 10-residue helix.

Making Bonds – bond and pbond: The bond command creates a covalent bond between two atoms, and ~bond breaks a bond. Syntax: bond <atom-spec1> <atom-spec2> [reasonable true|false]. Example: bond :50@NZ :200@OXT might bond a lysine NZ to an oxgyen (not chemically sensible, just example). By default, reasonable true only bonds if atoms are close enough to be plausible (within a distance cutoff). Set reasonable false to force a bond regardless of distance. Important: You can only form bonds between atoms in the same model. To bond atoms from different models, first combine them (see combine). The pbond command adds a pseudobond (non-covalent link, shown as a dashed line) between two atoms. Syntax is similar: pbond atom1 atom2. Pseudobonds are for annotations like connecting chain breaks or highlighting contacts, without chemical bonding.

Adjusting Bond Length – bond length: A subcommand of bond: Syntax: bond length atom1 atom2 <value> sets the bond length to the given value (Å). For example, if atoms A–B are bonded, bond length A B 1.55 will adjust that bond to 1.55 Å by moving the smaller fragment’s atoms. The move option (default small) determines which side of the bond moves. This is useful for idealizing certain bond lengths.

Adjusting Angles & Torsions – angle and torsion (modify): As mentioned under Measurements, giving an angle value to angle or torsion will rotate the relevant atoms to achieve that angle. For example, torsion :10@N :10@CA :10@CB :10@CG 60 rotates the χ1 dihedral of residue 10 to 60°. Use with caution.

Combining Models – combine: Merges specified models into a single model. Syntax: combine <model-spec> [newChainIds true|false] [copy true|false]. By default, combine #1 #2 would fuse models 1 and 2 into a new single model (likely with a new model number) without duplicating (i.e., removing originals). combine copy true would instead create a new copy, leaving originals untouched. This is needed if you want to create bonds between different original models or unify them for comparative modeling. Note: Chain IDs might conflict; by default it may change chain IDs to avoid overlap (control with newChainIds).

Renaming Chains – changechains: Changes chain IDs of a model’s chains. Syntax: changechains <spec> <newChainID>. You can supply multiple chain mappings. For example, if model #1 has chains A, B, C and you want them to be X, Y, Z: changechains #1/A=X #1/B=Y #1/C=Z. This is useful before combining models to avoid chain ID collisions.

Renumbering Residues – renumber: Renumbers residue sequence numbers. Syntax: renumber <residue-spec> start N [relative false]. By default, it maintains offsets (relative mode). For example, renumber #1/A start 1 relative false will renumber chain A in model 1 sequentially starting from 1 (ignoring existing numbering gaps). If relative true (default), it shifts existing numbers by a constant offset, preserving gaps. Use seqstart if you want to align with SEQRES numbering from PDB (advanced). Example: renumber :10-50 start 310 renumbers those residues to 310–350. Note: If the renumbering would cause duplicates (two residues same number in one chain), it will error and not perform the change.

Replacing Residues (Mutations) – swapaa and swapna: Mutates amino acids (swapaa) or nucleotides (swapna) in place. Syntax: swapaa <residue-spec> <new-residue-type> [criteria <rotamer-choice>]. Example: swapaa :45 ala mutates residue 45 to alanine using a default rotamer conformation. For multiple residues, you can provide a comma-separated list of new types matching the number of residues specified. The criteria or rotLib options let you choose how to pick a rotamer (e.g., best fit, random). swapna works similarly for DNA/RNA bases. Note: Only sidechain atoms are replaced; backbone stays the same. This is a quick mutation tool, but for multiple simultaneous mutations in a tight cluster, results may not be realistic due to clashes (consider using modeller in those cases). After swapaa, you might want to use addh to add hydrogens to the new sidechain, and maybe energy-minimize (ChimeraX does not have built-in minimization as of now, but can use external tools).

Model Refinement and Loops – modeller: If Modeller (an external program) is installed and licensed, modeller commands can build missing loops or do comparative modeling. For example, modeller loops #1 would attempt to fill missing segments in model #1 using Modeller (requires a license key for Modeller). Similarly modeller comparative can do homology modeling given a sequence alignment. These require setup and are beyond ChimeraX alone, but the command integration is provided.

Structure Prediction – alphafold and esmfold: These commands interface with external structure prediction:

AlphaFold – alphafold can fetch predicted structures from the AlphaFold DB by UniProt ID or run new predictions via Colab (internet required). Example: alphafold fetch P12345 retrieves the AlphaFold model for UniProt P12345 (if available in the AlphaFold Database). alphafold match <sequence> will search for a similar sequence in AlphaFold DB or run a new prediction if search true is used. It also can display predicted aligned error (PAE) plots and coloring by confidence automatically (the models come colored by pLDDT confidence by default). Note: For complexes, AlphaFold Multimer is not directly available in ChimeraX (AlphaFold DB has only single-chain). The alphafold collab option might be available to run ColabFold for a custom sequence or multiple sequence if configured. Also, predictions can take time and require internet; the command is interactive and will notify progress.

ESMFold – esmfold fetches from the ESM Metagenomic Atlas (which has millions of single-chain predictions) or runs the ESMFold algorithm on a given sequence. Example: esmfold fetch MGYP000542242899 retrieves a structure by its MGnify ID from the Atlas. esmfold match #1 will fetch predictions for the sequences of model #1’s chains (useful to get an ESMFold model for a protein you have sequence of). It also can color by confidence and show PAE like AlphaFold. Note: ESMFold is relatively fast and doesn’t require a separate installation (runs on a server). Like AlphaFold, treat predictions with caution and use confidence coloring to judge reliability.

Energy Minimization / Dynamics – tug and minimize: ChimeraX doesn’t have a full minimization command built-in, but tug is a interactive MD-based tool where you can pull atoms (requires OpenMM). Not extensively covered here, but be aware heavy modeling refinement might require external tools or Chimera (older).

Symmetry and Unit Cell – sym and unitcell: The sym command can generate symmetry-related copies of a model using crystallographic symmetry or BIOMT info. Syntax: sym #model [assembly n] [group PQR] ... etc. For example, sym #1 assembly 1 will create the biological assembly 1 for model #1 (if available). unitcell will show the crystallographic unit cell box and can generate all copies of the model in the unit cell. These are useful for crystal context.

Miscellaneous Modeling Tools: swapna (mutate nucleic acid), addh (add hydrogens), addcharge (charges) have been mentioned. Also delsolvent (no, that’s Chimera old, in ChimeraX just delete solvent). setattr can set any attribute on atoms, residues, etc., programmatically. Syntax: setattr <level> <attribute> <value> <spec>. For example, setattr r ribbonDisplays false protein would hide ribbons for all protein residues by setting their ribbon display attribute false. Or changing residue name via setattr r name UNK :5 as mentioned in docs for renaming a residue without coordinates change.

Volume Data and Density Maps

Opening Maps: Use open with map file (MRC/CCP4, EMDB ID, etc.) – see File I/O. Maps open as volume models (often model #N, type "Volume").

Volume Display – volume: Controls display settings of volume data (density maps). With no arguments, volume #N toggles the display of volume model #N. Common subcommands:

volume #N style <mesh|surface|solid> – choose display as mesh lines, surface, or solid volume.

volume #N level <threshold> – set contour level (for surface/mesh).

volume #N step <s> – adjust sampling (step 1 full resolution, step 2 half resolution, etc., for speed).

volume zone ... – similar to Surface Zone tool; volume #N zone <atom-spec> <distance> will crop the volume to a zone near specified atoms (like focus on density around a protein). For example volume #1 zone #2:1-100 5 would shown map #1 only within 5 Å of residues 1-100 of model #2. Use volume unzone to restore full map.

volume limitRange min,max – cut off density values outside range (for visualization).

volume colormap <name> – apply a different color map for solid display.

Segmentation Tools – segger/segmentations: ChimeraX has segmentation tools (from Segger extension). If you have segmented density, segmentation split or segmentation color commands might be available. These are advanced; typically one would use the GUI for segmentation.

Hiding Dust – hideDust: For density surfaces, hideDust can hide small disconnected blobs (“dust”) below a volume threshold size. This cleans up visualization by removing tiny isolated bits.

Volume Series – vseries: Handles an ordered series of maps (e.g., time series or tomogram slices). vseries play could play through them, etc. Similarly, mseries for multiple models (structures) in series.

Fitting Maps – fitmap: As noted in Measurements, fitmap moves one model to maximize correlation with a map. Example: fitmap #model into #map. After fitting, one might use measure correlation to get a numeric fit score.

Map Math – vop (volume operations): There’s a vop command to add, subtract, filter maps (e.g., vop add #1 #2 to add two maps, vop subtract #1 #2 etc., and vop filter gaussian sigma 3 #1). This is quite advanced but powerful for map processing.

Movements and Animation

Simple Translations – move: Moves (translates) models or atoms along a specified axis. Syntax: move <axis> [distance] [frames] [models <model-spec> | atoms <atom-spec>]. Example: move x 5 shifts the whole scene 5 Å to the right (X-axis) instantly (since frames default to 1). move z -10 frames 50 would shift everything 10 Å toward the camera over 50 frames (a smooth translation). You can target specific models: move y 3 models #2 moves model 2 up by 3 Å. Or specific atoms (which will move those atoms relative to the rest of the model – which cannot be undone easily). Note: If no model or atoms specified, the camera (scene) moves, not individual models. This is equivalent to shifting all models together.

Rotation – turn and roll: Rotates the view or models by a given angle around an axis. Syntax: turn <axis> <angle> [frames N] [models <spec>]. Example: turn y 90 rotates the scene 90° about the Y axis (vertical) in one step. turn z 180 frames 100 will make a half-turn around Z over 100 frames (useful in movies). If you specify models #1, it will spin model 1 relative to the rest (again, altering coordinates of model 1). roll is identical to turn except the default angle is 1° (good for continuous small rotations). So, roll y 1 repeated will spin continuously. Note: These rotations, if done on the scene (no specific model), are like using the mouse – they don’t change atomic coordinates, just the camera orientation. Rotating a specific model (models <#>) does change that model’s coordinates.

Rocking – rock: Oscillates rotation back and forth (like for creating a rocking animation). Syntax: rock <axis> <angle> [frames N] [cycle M] [models <spec>]. Example: rock y 30 cycle 100 will continuously rock ±30° around Y with 100 frames per full cycle. This goes on until stopped. Use stop to halt (also rock ... frames X to only do a certain total frames). Note: Good for presentation loops or to examine 3D structure.

Wobble – wobble: Performs a figure-eight rotation (a combination of two oscillations). Syntax: turn <axis> <angle> wobble M wobbleAspect f. But easier is roll ... wobble M. Actually, there's a separate wobble command that is like rock but figure-8. For example, roll y 20 wobble 100 might produce a figure-8 pattern with major rotation around Y 20° and minor around perpendicular axis scaled by wobbleAspect (default 0.3). This is more niche for fancy animations.

Stopping Motion – stop: Halts ongoing continuous motions like those started by turn frames, rock, roll (with cycles or forever). Just stop with no arguments stops all movements/rotations in progress. Good to use before starting a new movie segment or to end a rock.

Reset View – view and reset: ChimeraX doesn’t have a direct reset command like Chimera did, but view can save and restore named views. Syntax: view name <viewName> to save current camera view as <viewName>. Later, view <viewName> will restore it. e.g., view name start, then move things, then view start to jump back. Also view matrix prints the camera matrix (for advanced usage). If using a script and want to reset to default orientation, a workaround is to open a fresh session or if a “view default” was saved. There is also view orient to center and orient view on all models, and view center <spec> to center on a spec.

Interpolating Views – fly: Moves smoothly through a series of named views or specified orientations. Syntax: fly <viewName1> <viewName2> ... [frames N]. If you saved multiple view name positions, fly will interpolate between the current view and the next named one. For example, fly start end frames 200 goes from view "start" to view "end" over 200 frames. Or you can do multiple sequentially in one command. This is great for making smooth camera motions in movies.

Frame Updates and Waiting – wait: In scripts, commands like turn or movie operate over multiple frames asynchronously. wait N will pause execution of the script until N more frames have been displayed. For instance, if you do turn y 90 frames 90 followed by wait 90, it will ensure the turn finishes before the next command. wait with no number waits for all current motion commands to finish. This is essential in movie scripting to sync actions.

Per-Frame Actions – perframe: Allows executing a command on every frame during an animation loop. For example, you might use perframe "coordset #1 1,100" to animate a trajectory in coordination with something else on each frame. Or to update a label every frame, etc. This is advanced usage for complex scripted animations.

Trajectory Playback – coordset: Plays through coordinate sets (frames) of a trajectory model. If you open an MD trajectory (or a morph), it becomes a coordinate-set model. Syntax: coordset #model startFrame,endFrame,step [pauseFrames M] [loop N] [bounce true]. For example, if model #3 is a trajectory with 50 frames, coordset #3 1,50 will play from frame 1 to 50. coordset #3 50,1 would play backwards. You can also just jump to a specific frame: coordset #3 20 goes to frame 20. coordset stop #3 stops playback. Note: Use info #3 to see how many frames it has. You can use holdSteady @CA to minimize drift of CA atoms for visualization during playback. This command is primarily for movie-making or analyzing trajectories.

Morphing Trajectories – morph: Creates a morph between two or more structures (as a new trajectory model). Syntax: morph #model1,#model2[,#model3...] frames N. You must superimpose the structures first (e.g., with matchmaker). Example: morph #1,#2 frames 30 will generate a 30-frame morph from model 1 to model 2. It produces a new trajectory model (listed in Model Panel) that you can play with coordset. Options: wrap true makes the morph cycle back to the first structure (for looping); same true if morphing copies of the same structure with different conformations so that it knows to include all (some technical details). Note: Only the common atoms (by name/sequence) are interpolated. Morphing a trajectory of significant differences can show intermediate unphysical structures, so interpret accordingly.

Recording Movies – movie: Captures frames and encodes a movie file. Basic usage involves steps:

    movie record [options] – begin recording frames.

    Perform the desired motions/commands (e.g., rotations, coordset, etc., possibly using wait).

    movie stop – end frame capture (if you want to stop without encoding yet).

    movie encode [filename.mp4] [options] – encode captured frames into a video file.

For convenience, you can do movie record then after motions movie encode output.mp4 quality high. Or a one-liner: movie record; <commands>; movie encode output.mp4. There are many options:

movie record supersample N to render at higher res and downsample for smooth edges (N=3 recommended).

movie record size WxH to set resolution (otherwise uses window size).

movie record format png to save frames as PNG (for later manual encoding).

movie encode framerate 30 bitrate 6000 etc., to control output. movie formats lists available codecs.

movie crossfade N inserts N interpolation frames between the last captured frame and the next scene (for smooth transitions).

movie duplicate N duplicates the last frame N times (hold frame).

Example: To make a simple 360° spin movie:

movie record supersample 3
turn y 360 frames 180
wait 180
movie encode spin.mp4 bitrate 8000

This records a 180-frame (6-second at 30fps) smooth rotation.

Note: If you want to capture a user-driven manual rotation, you cannot use movie record in real-time (it captures offscreen by default). In that case, you’d use the GUI or a screen recorder. For scripted moves, the above method works. Always wait for motions to finish before encoding. movie abort cancels recording, and movie reset clears any saved frames if you want to start over.

Making Stops/Pauses: Use wait or insert duplicate frames as needed. For example, to hold on a view before moving: movie duplicate 30 will add ~1 second pause (at 30fps).

Combining Scenes: You can concatenate multiple segments by using movie record/stop multiple times and then one final encode (the captured frames accumulate until encoded or reset).

Miscellaneous Utilities and Scripting

Command Aliases – alias: Define shortcuts or macros for frequently used or long commands. Syntax: alias name command_list. Example: alias mmaker matchmaker $* allows you to type mmaker #1 #2 as a shortcut for matchmaker #1 #2. You can include arguments using $1, $2,... in the definition to refer to the first, second, etc. arguments when the alias is used. For instance, the built-in alias ribbon = cartoon $* means any arguments you give to ribbon are passed to cartoon. After alias ribbon cartoon $*, typing ribbon #1/A is equivalent to cartoon #1/A. Note: Aliases can chain multiple commands with ; in the definition. Example: alias home view original; reset positions (if such commands existed – hypothetical). List user-defined aliases with alias list, remove with alias delete name. Aliases are saved in sessions and can be put in startup file for automatic load.

Function Key Shortcuts – functionkey: Binds commands to F1–F12 keys. Syntax: functionkey <Fkey> "<command>". E.g., functionkey F5 "show sel" to assign F5 to show selected atoms. Useful for repetitive tasks during interactive use.

Running Scripts – runscript: Executes a script file (either ChimeraX commands .cxc or Python .py). Syntax: runscript <filename> [args]. For example, runscript myscript.cxc will run a text file containing ChimeraX commands line by line. If it’s a Python script, it runs in ChimeraX’s environment (with session available). You can pass arguments that the script can access via standard input (the script must be written to parse sys.argv). Alternatively, simply using open myscript.cxc will also execute a ChimeraX command file.

Undo and Redo – undo / redo: ChimeraX has limited undo functionality. undo will revert certain recent actions, and redo reapplies them. However, not all commands are undoable – generally, simple visibility or selection changes can be undone, whereas structural modifications (deletions, moves) cannot. The menu provides a single-level undo for some actions. Use with caution; check log messages to see if an action was added to undo stack.

Remote Control and REST – remotecontrol: Allows ChimeraX to accept commands from a REST API or another process. This is used for integrations (like sending commands from a Jupyter notebook or web interface). E.g., remotecontrol rest start to start the REST server. For average usage, not needed unless scripting externally.

Tool Administration – toolshed and devel: ChimeraX is extensible via bundles. toolshed install <bundle> or toolshed update can manage add-ons. The devel command is for developers to build or reload extension bundles.

Each command above can be combined and scripted to achieve complex tasks. By using this guide, an LLM or user can map natural-language instructions (e.g., "color the protein surface by hydrophobicity and show only chain A") to precise ChimeraX CLI operations (e.g., surface protein; mlp protein; hide ~:#A; show #1/A for that scenario). This comprehensive index of ChimeraX commands provides the building blocks for virtually any visualization or analysis workflow in ChimeraX.
